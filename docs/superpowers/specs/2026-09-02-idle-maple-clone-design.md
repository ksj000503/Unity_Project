# 방치형 게임(메이플키우기 모작) 설계 문서

- 작성일: 2026-09-02
- 상태: 브레인스토밍 승인 완료, 구현 계획 수립 대기

## 1. 개요

Unity 2D URP 기반 모바일 방치형(idle) 게임. "메이플키우기"를 참고한 모작으로, 캐릭터가 자동으로 몬스터를 처치하며 성장하는 핵심 루프를 가진다.

- 타겟 플랫폼: 모바일 (Android/iOS)
- 캐릭터 아트: 추후 사용자가 이미지 파일 전달 예정 (지금은 플레이스홀더)
- UI 아트: Claude가 제작, 임시 이미지도 추후 전달 (지금은 플레이스홀더 스프라이트/색상 블록)
- 백엔드: 없음. 로컬 저장만 사용 (계정/결제/광고 없음)

## 2. 아키텍처

매니저 기반 구조를 사용한다 (DOTS/ECS, 반응형 MVVM 프레임워크는 현재 규모에 불필요하여 채택하지 않음).

```
GameManager (전체 흐름 조정, 각 시스템 초기화/보관)
├── BattleSystem       — 자동전투 틱, 스테이지 진행, 처치 판정
├── EquipmentSystem    — 장비 드롭, 장착/해제, 장비 스탯 합산
├── EnhanceSystem       — 강화 시도, 성공/실패 판정, 강화석 소모
├── OfflineRewardSystem — 재접속 시 경과시간 기반 보상 계산
└── SaveSystem          — 로컬 JSON 저장/로드, 자동저장 주기 관리
```

- 시스템 간 통신은 C# 이벤트/델리게이트로 한다 (예: `OnMonsterKilled`, `OnLevelUp`, `OnEquipmentDropped`, `OnEnhanceResult`). 시스템끼리 직접 참조하지 않고 이벤트로 느슨하게 연결한다.
- 몬스터/장비/스테이지 정의는 ScriptableObject 데이터 에셋으로 관리한다. 밸런스 수치는 코드가 아니라 에셋에서 조정한다.
- 코드 스타일은 project.txt에 명시된 규칙을 따른다: 단순하고 읽기 쉽게, 그러나 기능 생략이나 예외처리 누락 없이. 불필요한 추상화/디자인패턴 금지(YAGNI). 함수는 짧게, 스크립트는 한 가지 역할만. 주석은 '왜'만 짧게. 여러 구현 가능성이 있으면 시간복잡도 계산 후 더 빠른 알고리즘 채택.

## 3. 전투 / 스테이지 진행

- 스테이지는 선형 구조다 (1-1, 1-2, 1-3 ...). 각 스테이지는 목표 처치 수를 가지며, 달성 시 다음 스테이지로 자동 이동한다.
- 전투는 틱 기반 자동전투다: 몬스터 자동 스폰 → 캐릭터가 공격속도 간격으로 자동 공격 → 몬스터 처치 시 골드/경험치 지급 및 장비 드롭 판정.
- 데미지 계산, 경험치/레벨업 곡선은 순수 함수(로직)로 구현하여 유닛 테스트가 가능하게 한다.
- 레벨업 시 캐릭터 스탯(공격력/체력 등)은 공식 기반으로 자동 증가한다. 수동 포인트 배분은 없다.

## 4. 장비 시스템

- 슬롯 4개: 무기 / 모자 / 옷 / 액세서리.
- 등급 4단계: 일반 → 희귀 → 영웅 → 전설. 등급이 높을수록 기본 스탯이 높고 드롭 확률은 낮다.
- 몬스터 처치 시 확률적으로 드롭한다 (등급별 드롭 가중치는 ScriptableObject에서 설정).
- 장착 시 장비 스탯이 캐릭터 기본 스탯에 합산된다.

## 5. 강화 시스템

- 강화석(별도 재화)을 소모해 장착 장비를 강화한다.
- 강화 단계가 오를수록 성공률이 하락한다(공식으로 계산, 단계별 하드코딩 표 지양).
- 강화 실패 시 강화 단계가 1단계 하락한다 (장비 파괴 없음).

## 6. 재화

- 골드: 전투 보상 및 일반 소모(장비 관련 기타 비용)에 사용.
- 강화석: 강화 전용 재화. 몬스터 드롭 및 스테이지 클리어 보상으로 획득.

## 7. 오프라인 보상

- 마지막 접속 시각을 저장해두고, 재접속 시 경과 시간을 계산한다.
- 경과 시간은 최대 8시간까지만 인정하고 초과분은 버린다.
- 정산 보상(골드/경험치)은 평소 초당 평균 처치 수를 기준으로 시뮬레이션한 값으로 계산한다.
- 오프라인 보상 계산 로직은 순수 함수로 구현해 유닛 테스트를 작성한다.

## 8. 저장 시스템

- 로컬 JSON 파일로 저장한다 (계정/서버 없음, 기기별 독립).
- 자동저장 주기(예: 30초)마다 저장하고, 앱 일시정지(`OnApplicationPause`) 및 종료(`OnApplicationQuit`) 시점에도 저장한다.

## 9. UI 구조

- 하단 탭바로 화면을 전환한다: 전투 탭 / 장비 탭 / 강화 탭.
- 전투 탭이 메인 화면이다 (캐릭터, 몬스터, 스테이지 진행바 표시).
- 장비/강화 탭은 별도 화면으로 구성한다.
- 캐릭터/UI 아트는 아직 없으므로 플레이스홀더(단색 스프라이트, 기본 UI 요소)로 우선 구현하고, 이후 실제 이미지로 교체 가능한 구조로 만든다 (스프라이트를 하드코딩하지 않고 인스펙터에서 교체 가능하게).

## 10. 테스트 전략

- 순수 로직(데미지 계산, 레벨업 곡선, 강화 확률/단계 로직, 오프라인 보상 계산식)은 유닛 테스트로 검증한다 (Unity Test Framework, Edit Mode 테스트).
- MonoBehaviour와 얽힌 UI/씬 연동부는 에디터에서 수동 확인한다.

## 11. 범위 밖 (Out of Scope)

- 계정 시스템, 서버 연동, 결제, 광고 — 전부 명시적으로 제외.
- 장비 무한 파괴 강화 페널티, 수동 스탯 분배, 무한 웨이브 모드 — 채택하지 않음(선형 스테이지로 결정).

## 12. 참고

- 프로젝트에는 `mcp-unity` MCP 서버가 이미 연결되어 있음 (`.mcp.json`). Unity 에디터 조작(바이브 코딩)에 활용 가능.
